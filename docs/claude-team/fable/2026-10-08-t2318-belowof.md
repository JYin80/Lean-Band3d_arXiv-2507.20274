## 1. The defect, restated at the source

- `belowOf` (`LWExpCert.lean:157-190`) skips a dotted choice `c` iff `(X0 ++ X1).any (labs u == labs v)` with
  `X0 := (Δ.dotted.filter (!eq)).map pairOf` (`:162`) — every `×`-edge of `Δ`.
- The real term is `Δ.withDots c` with `dotted := Δ.dotBase ++ c.2` (`LWVocab.lean:1091-1095`), `dotBase` dropping the
  b-edges (`isB`: `×` with no solid edge between the ends, `:1066-1073`); its consistency (`Consistent`, `:1267`) and
  the model merge `cMerge (Δ.withDots c)` (`LWExpCert.lean:87-98`) test only the `×`-edges of `dotBase ++ c.2`.
  Paper `dot-def` (`7_8:215-221`): for a b-edge `1_{α≠β} = 1 − 1_{α=β}`; after this rewrite the `×` edge is gone from both
  terms, so the merge term `−1_{α=β}` is a legitimate (consistent) term.
- `cPartition`/`cPartitionX` (`:100`, `LWExpSim.lean:177`) go through `cMerge (Δ.withDots c)` and are therefore exact
  (T2311's `partitionSim` is unaffected). Only `belowOf` (flag + below-target list), hence `childrenB`, `goodB`,
  `rootInfo`, `cert_all`, is wrong: the choices with a b-edge inside an `=`-class are neither flagged nor listed.
- Where b-edges come from: a node `N` is normal (every `×` has solid support, `partition_normal`), the `(Oe2x)` family
  graphs delete `p = G_{xy}`, `q = G_{y'x}` (and `q'` for `R7/R8`) and keep `Δ.dotted` (`owxExt`, `LWWeightExp.lean:462`),
  so the `×`-edges at `(x,y)`, `(y',x)`, `(s,t)` of `q'` lose their support unless a parallel solid edge remains. Hand check
  at root term 9, candidate 0, family `R2` (`T2318-prove.md` (a) (ii) rows `R2 2 7 2`): 2 b-edges `(a,c)`, `(x+y,a)`, one
  aPair `(x+y,c)` (new `G_{y'y}`), 8 choices, 1 inconsistent (`a ~ c ~ x+y` with `×(x+y,c)`), 7 real terms, `belowOf`
  evaluates only the 2 with both b-edges dropped. A lost term: `a ~ c ~ x+y` with `=(x+y,c)`: `B = 1`, `L = 1`
  (`G_{x+y c}` becomes an external loop), `n_S = 3`, `n_W = 3`, `tg = 4`, `ord = 7 − t ≥ 6` — a leaf, `n_M = 0`.

## 2. Options

**(A) corrected flag + new certificate pair.** `belowOf'` := `belowOf` with the one line
`X0 := (Δ.dotBase.filter fun e => !e.eq).map (pairOf a b)` (exactly the `×`-edges that `cMerge (Δ.withDots c)` tests, so
`skip ↔ cMerge (Δ.withDots c) ext = none ↔ ¬ Consistent (Δ.withDots c)` by `List.filter_append` and `isB e → ¬ e.eq`;
everything else (`labs`, `B`, `L`, `tg`, `ok0`, the list) already reads the same `=`-edges as the real term). New files
`Graph/LWExpCertB` (~170 lines: `belowOf'`, `childrenB'`, `goodB'`, `rootInfo'`, `rootAt'`, `kids'`, `kidsOk'`, `kid'`,
`goodB'_succ_of`, instances, a diagnostic `lostOf`/`lostAt`), `LWExpCertBS0`, `LWExpCertBS1` (verbatim copies of T2306's
S0/S1 with primes, ~300 each; the chunk shape — 11 root terms, 12/14 kids per candidate at terms 9/10 — is unchanged because
the mirror found 0 lost non-leaves). Merged files untouched (CLAUDE.md §5.3 "primed successor"). T2318 Amend 1 restates
`BelowOfSound`/`SoundStep`/`SoundRoot` with the primed names; L7 becomes *simpler* (the test is now literally `cMerge`'s).
Correctness risk: low (one line, the mirror's `lost2.py` already says flag true and list unchanged at every node for both `s`;
the kernel re-checks it: a lost non-leaf would change a `(kids' …).length` and the chunk theorem would fail). Lean size
≈ 780 lines, no new mathematics. Build: three modules alone (H101); the kernel now evaluates `ok0` on ~1.75× as many choices
(70253 + 52799 for (F,F)), the union-find part is unchanged, so S0/S1 ≈ 1.3–1.8 × (564 s, 621 s) ≈ 12–19 min each, memory
7.0 GB → 7.5–9.5 GB on the heaviest chunk (`ch_FF_10_0_8'`): the 8 GB limit may be hit, so the ticket measures that chunk first
and pre-authorises the per-candidate split (`kidsOk' K j ∧ (kids' K j).length = m` per candidate, `goodB' 1` per depth-2 kid,
assembled by `goodB'_succ_of`; ~36 depth-2 inner nodes per `s`). New LW tickets: 1 (T2319; LW plan 47 → 48).

**(B) keep `cert_all`, add a kernel check of the skipped choices + a cover lemma.** The skipped set lives at 3061 of 3394
family graphs, so the check must re-traverse the same tree (`cands`, `fams`, `dotChoices`, `labsOf` at every node) and
re-evaluate `ok0` on the 52799 lost choices: the kernel cost is the cost of (A) (the union-find part is repeated, the `ok0`
part is the increment), plus a second AND-tree (`goodL`) with its own chunk files (~600 lines) and, in T2318, a case split
in L7 on two folds and the lemma "real = covered ∪ skipped" (+150–250 lines, two certificates to keep aligned). Strictly
worse than (A) on every axis except that `cert_all` stays "used".

**(C) a lemma without a kernel run ("b-edge-merge terms are leaves with the properties").** Not available as a short
argument. Merging the ends of a b-edge raises `ord` by 2 only when an internal vertex disappears (both ends external:
`ord` unchanged, `tg` may drop 5 → 4), and it can create new uncircled loops from the *new* solid edges (old solid edges
never become loops in a consistent term, since their `×` support is kept; `G_{αy}`, `G_{y'α}`, `G_{y'y}`, the derivative
edges can), each dropped loop costing 1: in `R4/R6/R8` the drop-term itself can carry `t = 2`. So the crude bound is
`ord − tg ≥ (ord(N) − tg(N)) + 3 − t` with `ord(N) − tg(N) = −2` at the worst root terms (term 9: `(2, 4)`), i.e. `≥ 1 − t`,
not `≥ 0`. The leaf *properties* (`n_M ≤ 1`, the attachment count `≥ 2` at every internal molecule, distinct external
molecules ∨ `LWJoined`) are not monotone under merges either. A hand proof would be a case analysis over 7 families × up
to 3 b-edges × the other choices — the "verified by inspecting" of `B:98` that DECISIONS §95 (1)/§107 (3) replaced by the
kernel certificate on purpose. Also no cancellation shortcut: for a b-edge whose ends are already joined by other `=`
choices the drop and merge terms cancel in value, but both are members of `expandRoot selClassical 4` (T2307's list is
fixed and `LWG5Expand'` quantifies over every member), so the leaf properties must hold for each. Rejected.

**Decision: (A).** Cheapest in proof lines, one line of new code, the only cost is one more exclusive kernel build per
stage (≈ 3 × 30–40 min of machine time, H101), and T2318's L7 gets easier.
